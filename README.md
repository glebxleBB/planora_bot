# 📅 Бот для записи в сервисы

Telegram-бот для удобной записи в любые сервисы: клиент находит нужное заведение, выбирает услугу и дату и записывается, не звоня и не переписываясь. Владельцы сервисов сами регистрируют свои заведения и получают уведомления о записях.

> 🚧 **Это MVP.** Сейчас в боте доступна только одна категория — **парикмахерские**. Структура проекта (роли «Клиент» и «Сервис», выбор категории) рассчитана на добавление других типов сервисов.

## Возможности

**Клиент**
- выбирает город и категорию, смотрит список одобренных заведений (пока парикмахерские);
- видит адрес, телефон и услуги с ценами;
- выбирает услугу, вводит дату (`ДД.ММ.ГГГГ`) и подтверждает запись;
- не может записаться на прошедшую дату, на нерабочий день или дальше чем на 60 дней вперёд;
- не может дважды записаться на одну услугу в один день.

**Владелец сервиса**
- проходит пошаговую регистрацию: название, город, адрес, телефон, услуги с ценами, рабочие дни и часы;
- перед отправкой проверяет все данные и может начать заново;
- получает уведомление о решении администратора и о каждой новой записи.

**Администратор**
- получает карточку каждой новой заявки с кнопками «Одобрить» / «Отклонить»;
- командой `/pending` открывает все необработанные заявки.

## Стек

- Python 3.10+
- [pyTelegramBotAPI](https://github.com/eternnoir/pyTelegramBotAPI)
- SQLite (создаётся автоматически)

## Установка и запуск

1. Клонируйте репозиторий и установите зависимости:

   ```bash
   git clone <адрес-вашего-репозитория>
   cd barbershop-bot
   pip install -r requirements.txt
   ```

2. Создайте бота у [@BotFather](https://t.me/BotFather) и скопируйте токен.

3. Узнайте свой Telegram ID, например у [@userinfobot](https://t.me/userinfobot). Это ID администратора, на него будут приходить заявки.

4. Создайте файл `.env` по образцу `.env.example`:

   ```env
   BOT_TOKEN=токен-от-BotFather
   ADMIN_ID=ваш-telegram-id
   ```

5. Запустите бота:

   ```bash
   python bot.py
   ```

   База данных `barbershops.db` создастся рядом с кодом при первом запуске.

> ⚠️ Администратор должен хотя бы раз написать боту `/start`, иначе Telegram не позволит боту отправлять ему сообщения. Если `ADMIN_ID` не задан, бот запустится, но одобрять заявки будет некому.

## Настройки

| Переменная | Описание |
|------------|----------|
| `BOT_TOKEN` | Токен бота от @BotFather (обязательно) |
| `ADMIN_ID` | Telegram ID администратора (нужен для одобрения заявок) |

Прочие параметры задаются в коде:

| Параметр | Где | По умолчанию |
|----------|-----|--------------|
| Список городов `CITIES` | `utils.py` | Петропавловск |
| Часовой пояс `TZ` | `utils.py` | UTC+5 |
| Максимум дней вперёд для записи `MAX_DAYS_AHEAD` | `client.py` | 60 |
| Заявок на проверке от одного владельца `MAX_PENDING_PER_OWNER` | `service.py` | 3 |
| Максимум услуг, длина названий, максимальная цена | `service.py` | 20 / 64 символа / 1 000 000 ₸ |

## Структура проекта

```
├── bot.py            # точка входа, меню /start, регистрация обработчиков
├── config.py         # чтение BOT_TOKEN и ADMIN_ID из .env
├── client.py         # сценарий клиента: выбор и запись
├── service.py        # сценарий владельца: регистрация заведения
├── admin.py          # проверка заявок администратором
├── db.py             # работа с SQLite
├── utils.py          # общие константы и вспомогательные функции
├── .env.example      # пример настроек
└── requirements.txt
```

## Как это работает

1. Владелец регистрирует своё заведение, заявка сохраняется со статусом `pending`.
2. Администратор получает карточку и одобряет или отклоняет заявку.
3. Одобренные заведения становятся видны клиентам.
4. Клиент записывается на услугу, а владелец получает уведомление.

## Планы развития

- новые категории сервисов помимо парикмахерских;
- новые города;
- выбор конкретного времени записи;
- личный кабинет владельца: просмотр и отмена записей;
- хранение состояния диалогов между перезапусками.

## Ограничения

- Состояние диалогов хранится в памяти: после перезапуска бота незавершённая регистрация или запись сбрасывается. Сами данные в базе сохраняются.
- Запись делается на дату, без выбора конкретного времени: заведение само связывается с клиентом для уточнения.
- Если у клиента нет username в Telegram, владелец видит только его ID.

## Безопасность

Не публикуйте файл `.env` и базу `barbershops.db`: в них токен бота и персональные данные пользователей. Оба файла уже добавлены в `.gitignore`. Если токен случайно попал в репозиторий, перевыпустите его через `/revoke` в @BotFather.
